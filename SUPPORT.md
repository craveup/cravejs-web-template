# Support

## Project questions

After the repository is publicly released, use GitHub issues for reproducible bugs and bounded
feature proposals. Search first and include the exact template release or commit, runtime profile,
fixture/tenant, browser/device, reproduction steps, expected result, actual result and verification
commands.

Do not use public issues for credentials, customer data, restaurant configuration, security reports
or urgent production incidents. Vulnerabilities follow [SECURITY.md](SECURITY.md).

## What is not supported here

- retired Storefront SDK 1.x integrations and the legacy bakery, sushi, noodle-house or AI-template
  repositories;
- generated projects that cannot identify their exact template release and provenance;
- mutable-branch templates, copied private platform code or browser Crave API keys;
- unverified third-party forks, payment-provider code embedded in the storefront, or production
  fixture fallbacks; and
- Make, which is a conceptual owner-to-developer design exercise rather than a production builder or
  support path.

## Professional implementation help

Open-source project support and paid Crave services are separate. Restaurant groups and enterprise
teams seeking design, integration, rollout or managed operations can contact
[hello@craveup.com](mailto:hello@craveup.com). A services engagement does not change the public
project's security, review or release gates.

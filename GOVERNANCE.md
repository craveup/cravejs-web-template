# Project governance

Crave.js Restaurant Storefront is maintained by Crave Up. It is being prepared as the canonical web
reference for the public Crave Storefront API and SDK.

## Decision ownership

Crave maintainers have final responsibility for scope, contracts, security, releases, repository
settings and merge decisions. Contributors can propose and implement work through issues and pull
requests; acceptance depends on evidence and the documented ownership boundaries, not on sponsorship,
customer status or contribution volume.

Changes to public API/SDK compatibility, tenant or capability authority, checkout, money,
authentication, generated-starter provenance, release signing, license, governance or security policy
require explicit maintainer approval. Presentation changes still require design, accessibility,
localization and shared-core evidence.

## Release model

The web template releases independently from the Crave Storefront API, Storefront SDK, CLI and Expo
template. A public template release must identify exact compatible versions and integrity evidence.
No branch, prerelease preview or README claim substitutes for a signed immutable release.

Repository visibility, license approval, merge approval, tag creation, release publication, CLI
registry activation and deployment are distinct decisions. Passing tests authorizes none of them by
itself.

## Sponsorship independence

Sponsors may be acknowledged after mutual written approval. Sponsorship does not buy roadmap control,
merge rights, security exceptions, access to private repositories or customer data, endorsement,
release priority, or a guarantee that a proposed feature will ship.

Crave may decline funding that conflicts with restaurant trust, platform safety or project
independence. Paid implementation services are contracted separately from project sponsorship.

## Changes to governance

Propose governance changes through a dedicated issue and pull request. The change must explain the
problem, affected participants, decision rights, transition and conflicts of interest. Maintainers
record accepted changes in this file before relying on them.
